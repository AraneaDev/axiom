# GitHub fixtures

These are the answers of the recorded GitHub fake in `src/test/github-fake.ts`. Each JSON file holds one route, as `{ "route": "GET /repos/:owner/:repo", "status": 200, "body": {...} }` with an optional `"headers"` object; `:name` segments match any one path segment, and a literal route wins over a parameter route. Every body is a trimmed copy of the response example GitHub publishes in its REST reference for API version 2022-11-28, with every account, repository, id and URL replaced by invented ones (`acme-labs/widget`, `octo-dev`, `review-bot`): never a real account, and never a token or key. `base/` is always loaded; a scenario directory beside it (`useGithubFake('<scenario>')`) is loaded on top of it, and its routes win. To add a fixture, copy the example from the endpoint's page in the REST reference, keep only the fields a test or the code reads, replace the names, and save it under `base/` (or a scenario) with a file name that says what it answers, such as `get-repo.json`.
