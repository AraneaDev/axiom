# GitHub fixtures

These are the answers of the recorded GitHub fake in `src/test/github-fake.ts`. Each JSON file holds one route, as `{ "route": "GET /repos/:owner/:repo", "status": 200, "body": {...} }` with an optional `"headers"` object; `:name` segments match any one path segment, and a literal route wins over a parameter route. Every body is a trimmed copy of the response example GitHub publishes in its REST reference for API version 2022-11-28, with every account, repository, id and URL replaced by invented ones (`acme-labs/widget`, `octo-dev`, `review-bot`): never a real account, and never a token or key. `base/` is always loaded; a scenario directory beside it (`useGithubFake('<scenario>')`) is loaded on top of it, and its routes win. The fixtures hold bodies only; who may see them is the fake's state, as on GitHub: `setApp`, `addInstallation(id, repos)`, `issueInstallationToken`, `issueUserToken(login, repos)` and `setPublicRepos` decide which `/repos/:owner/:repo` calls answer and which get 404 or 403, and `/installation/repositories` is filtered to the installation's repositories. To add a fixture, copy the example from the endpoint's page in the REST reference, keep only the fields a test or the code reads, replace the names, and save it under `base/` (or a scenario) with a file name that says what it answers, such as `get-repo.json`.

Some routes answer from the fake's state and not from a file: `POST /app/installations/:id/access_tokens`, `GET /app/installations` and `POST /app-manifests/:code/conversions`. The last one takes its App from `base/convert-manifest.json`, swaps in a freshly generated private key, registers the App's public key with the fake, and accepts only a code from `issueManifestCode()`, once.
